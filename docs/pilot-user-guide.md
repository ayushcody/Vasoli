# Using the private pilot

1. Sign in with an invited account. In Settings, add each INR bank, cash or wallet account you want to plan from. Enter the balance you actually checked and use **Confirm balance** to record when you checked it. Older records remain Unassigned until you choose an account.
2. Open Activity and import a CSV into its owned account. Add opening and closing statement balances when available. Review the server's rejected rows, possible duplicates and balance comparison before committing. A possible duplicate can be a genuine repeat; you can include it. Skipping invalid rows requires explicit confirmation. A failed commit can be retried safely with the same preview.
3. Assign old Unassigned records in Activity. Search and filters cover the complete ledger; the CSV download contains all matching records, including records beyond the current page.
4. Record internal movements with **Transfer** between two owned accounts. For a card payment, use the bank account as source and the credit-card ledger as destination. Purchases remain expenses; paying the card is a transfer. Enter outstanding card debt as a negative account balance. When importing both sides of a movement, explicitly exclude the matching movement rows and record one linked transfer, so you do not count it twice. The pilot does not automatically infer that a bank withdrawal is a card payment.
5. Add or confirm bills in Obligations and select the paying account. Mark a scheduled occurrence paid when you have paid it, including an early payment for a future due date. Link an existing payment from Activity when it was already imported. Only create a new expense after confirming it is missing; the app records the payment and does not move money. Keep the recorded account balance and actual payment records current. Download a selected bill from its menu or all active bills as calendar events.
6. Create a goal, then open **Cashflow** to set a future payday, paying accounts, daily spending allowance, minimum reserve, one goal and the amount you want protected for that goal. Review the resulting position on **Today**. A goal reservation protects money in the calculation; it does not create an expense or move money.
7. Review warnings, the lowest projected cash and individual account shortages. The day before payday is the last forecast day; future salary is not currently spendable. Confirm balances older than seven days before relying on an estimate. Extra-expense scenarios use the same server calculation and do not change your records.
8. Review a suggested action, then complete, dismiss or snooze it. Missing data still needs to be resolved even if you dismiss a task. Settings provides a complete JSON data export and explicit account deletion with a visible result and retry on failure.

Marco is optional and disabled in the default pilot configuration. Core records and planning do not depend on AI. Statement files are not retained by default. Keep exported financial files private.
